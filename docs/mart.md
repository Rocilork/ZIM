# Витрина `hourly_demand`. Seoul Bike

## 1. Модель

**Выбранный вопрос** (основной из [Project Brief](project_brief.md)): как различается
почасовой спрос на велосипеды в Сеуле по сезону, часу суток и типу дня (рабочий,
выходной, праздничный)?

**Гранулярность.** Одна строка `hourly_demand` представляет **один час работы системы
велопроката в определённую дату** — то же, что и строка `staging`. Исходные данные уже
агрегированы по часам, поэтому уровень детализации сохранён: `count(*)` считает часы
наблюдений, а число аренд хранится отдельной мерой `rented_bike_count`.

**Ключ.** Надёжного бизнес-ключа в источнике нет: отдельная поездка в данных не видна.
Сочетание `observed_on` + `hour` уникально (0 пропусков, 0 повторов — проверено в ноутбуке),
и это подтверждает заявленную гранулярность. Однако уникальность часа наблюдения
**не доказывает** уникальность реальных событий: разные поездки одного часа неразличимы
по построению набора. Поэтому технический идентификатор строки не создавался, `DISTINCT`
для искусственной уникальности не применялся, а кратность строк сохранена.

**Меры и правила агрегации:**

| Мера | Единица | Использование в вопросе | Допустимость агрегации |
|---|---|---|---|
| `rented_bike_count` | Аренды за час | Основная метрика: сумма и среднее по группам | Суммируется по непересекающимся группам одного снимка. Средние групп нельзя усреднять без учёта размера групп |
| `hour` | Час суток 0–23 | Срез: сравнение по часам | Признак группировки, не мера |
| `temperature_c` | °C | Уточняющий вопрос о погоде | Не суммируется как итог; для анализа связи применяется с оговорками |

Меры нельзя складывать между разными снимками источника: один и тот же час может попасть
в два снимка. Набор содержит один непрерывный период, поэтому это ограничение касается
будущих загрузок.

**Обоснование структуры: одна широкая таблица.** Все необходимые атрибуты — сезон, тип дня,
календарные признаки и погодные показатели — уже находятся в одной строке `staging`
с согласованной гранулярностью. Отдельных справочников у набора нет: `season` и `holiday` —
короткие перечисления прямо в данных, а не таблицы измерений, поэтому выделять их
в отдельные объекты `mart` значило бы добавить соединение без пользы для вопроса. Широкая
таблица сохраняет исходную кратность строк и упрощает проверку баланса со `staging`.
`JOIN` в модели не используются.

**Временные поля.** `observed_on` — время наблюдения (дата события). `source_ingested_on`
в пути объекта — логическая дата загрузки в слой `raw`, она не является временем события
и в витрину не переносится.

## 2. Сопоставление полей

| Поле в `hourly_demand` | Поле в `staging` | Преобразование | Смысл, единица или ограничение |
|---|---|---|---|
| `observed_on` | `observed_on` | Перенос без изменения | Дата наблюдения |
| `hour` | `hour` | Перенос без изменения | Час суток, 0–23 |
| `rented_bike_count` | `rented_bike_count` | Перенос без изменения | Число аренд за час, ≥ 0 |
| `season` | `season` | Перенос без изменения | Сезон: Spring, Summer, Autumn, Winter |
| `holiday` | `holiday` | Перенос без изменения | Исходный признак: Holiday / No Holiday |
| `day_type` | `holiday`, `observed_on` | `CASE`: `праздник`, если `holiday = 'Holiday'`; иначе `выходной`, если ISO-день 6 или 7; иначе `рабочий` | Тип дня для среза вопроса. Приоритет у праздника |
| `month` | `observed_on` | `EXTRACT(month)` | Месяц, 1–12 |
| `day_of_week` | `observed_on` | `EXTRACT(isodow)` | ISO-номер дня недели: 1 — понедельник, 7 — воскресенье |
| `week_of_year` | `observed_on` | `EXTRACT(week)` | Номер недели ISO, 1–53 |
| `functioning_day` | `functioning_day` | Перенос без изменения | Исходный признак работы сервиса |
| `service_closed` | `service_closed` | Перенос без изменения | Признак ЛР № 3: час остановки сервиса |
| `is_open` | `service_closed` | `NOT service_closed` | Обратный признак для удобного фильтра открытых часов |
| `temperature_c` | `temperature_c` | Перенос без изменения | Температура воздуха, °C |
| `humidity_pct` | `humidity_pct` | Перенос без изменения | Относительная влажность, % |
| `wind_speed_ms` | `wind_speed_ms` | Перенос без изменения | Скорость ветра, м/с |
| `rainfall_mm` | `rainfall_mm` | Перенос без изменения | Осадки за час, мм |
| `snowfall_cm` | `snowfall_cm` | Перенос без изменения | Снег за час, см |
| `humidity_zero_flag` | `quality_humidity_zero_is_suspicious_violated` | Переименование без изменения значений | Флаг ЛР № 3: нулевая влажность (17 строк) |
| `warm_snowfall_flag` | `quality_snowfall_requires_cold_violated` | Переименование без изменения значений | Флаг ЛР № 3: снег при температуре ≥ 5 °C (14 строк) |

Приоритет праздника над выходным нужен потому, что четыре праздника в наборе выпадают
на субботу или воскресенье (24.12.2017, 31.12.2017, 17.02.2018, 23.09.2018). Без приоритета
такие дни попадали бы сразу в две группы, и суммы по группам перестали бы сходиться
с общим итогом.

**Фильтрация не применяется: исключённых строк нет** (8760 = 8760 + 0). Это продолжение
решений ЛР № 3:

- 295 часов остановки сервиса остаются с признаком `service_closed`. В ЛР № 3 они признаны
  реальным состоянием системы, а не ошибкой данных. Удаление здесь было бы новым решением
  о качестве; кроме того, оно молча подняло бы средний спрос с 704.6 до 729.16 аренды в час.
- Строки с флагами влажности и снега сохранены: сомнительно только погодное значение,
  а число аренд в этих часах достоверно.

**Ограничения дальнейшего анализа:**

- Бизнес-ключа нет, поэтому доказать уникальность реальных поездок нельзя. Витрина
  сохраняет кратность строк, но не подтверждает, что каждый час — независимое событие.
- Данные агрегированы по часам: длительность поездки и маршрут по ним не изучаются,
  а фактический спрос может быть выше наблюдаемого.
- Часы остановки сервиса (295) остаются в витрине. Для метрик спроса их следует
  исключать фильтром `is_open`, иначе среднее окажется заниженным. Заметно, что все эти
  часы приходятся на 13 дней весны и осени (247 часов осенью и 48 весной), а летом и зимой
  остановок не было — это влияет на сравнение сезонов.
- Средние значения групп нельзя усреднять без учёта размера групп, а медиану нужно
  пересчитывать по исходным значениям. Число часов в группах сильно различается:
  от 48 (лето, праздники) до 1536 (лето, рабочие дни).
- Суммы аренд по группам складывать можно, но это не «выручка» и не число уникальных
  пользователей: одна поездка может учитываться иначе, а сам показатель — число аренд.
- Погодные показатели — наблюдения метеослужбы, а не условия в точке аренды. 17 часов
  с нулевой влажностью и 14 со снегом при тёплой температуре помечены флагами; при расчёте
  связи по этим полям их следует исключать.
